# Инструкция для команды: проект Hotel Booking System

Этот файл для всех участников. Прочитай его целиком (10 минут), и ты будешь понимать, что в проекте уже сделано, как это запустить и что делать дальше.

---

## 1. Что у нас есть

Сайт бронирования отеля на 40 комнат (учебный проект GrandStay Hotel). Он состоит из трёх частей, и они уже соединены между собой:

```
 БРАУЗЕР (frontend)  ──fetch, JSON──▶  СЕРВЕР (backend)  ──SQL──▶  БАЗА ДАННЫХ
 HTML + CSS + JavaScript               Node.js, server.js          SQLite, hotel.db
```

**Что умеет сайт**
- Гость выбирает даты и тип комнаты, видит, сколько комнат свободно.
- Вводит данные и оплачивает бронь картой (оплата имитируется).
- Получает номер брони и «письмо» с подтверждением.
- Находит свои брони по email и может их отменить.
- Сотрудник видит все брони, доску комнат на выбранный день и может подтвердить оплату «на стойке».
- Есть тесты из Task 07: 50 одновременных запросов на одну комнату сохраняют только 1 бронь, 100 бронирований не теряются.

**Что настоящее, а что имитация**

| Часть | Статус |
|---|---|
| Сайт (страницы, форма, проверка полей) | настоящий |
| Сервер и HTTP API | настоящий |
| База данных SQLite (таблицы из ER-диаграммы) | настоящая, данные сохраняются |
| Расчёт цены на сервере, защита от двойной брони | настоящие |
| Оплата картой | имитация (нет реальных денег) |
| Отправка email | имитация (письмо записывается в таблицу `email_outbox`) |

## 3. Как запустить (5 минут)

1. Установи **Node.js 22.5 или новее** (сайт nodejs.org, версия LTS). Проверка: в терминале `node -v`.
2. Скачай проект: `git clone -b frontend-backend-site https://github.com/hassenovv/HotelBookingSystem` (проект лежит в ветке `frontend-backend-site`).
3. Запусти сервер:
   - **Windows:** двойной клик по `start-server.bat`
   - **Mac/Linux:** `./start-server.sh`
4. Открой в браузере **http://localhost:3000**. Вверху справа должна быть зелёная плашка «● Backend connected».
5. Страница **Backend** (меню сверху) показывает доказательство связи: запросы сайта к серверу и строки из базы.

Устанавливать пакеты (`npm install`) не нужно. Окно терминала с сервером не закрывай: в нём печатается каждый запрос.

Если плашка серая «Demo mode», значит сервер не запущен, а сайт работает на встроенной имитации.

## 4. Как всё работает (на примере бронирования)

1. Гость нажимает «Pay» на странице `booking.html`. Скрипт `booking.js` проверяет поля, превращает номер карты в токен (сама карта стирается) и вызывает `HotelApi.createBooking(...)`.
2. `api-client.js` отправляет запрос `POST /api/bookings` на сервер в формате JSON. В запросе **нет цены и нет номера карты**.
3. `backend/server.js` на сервере:
   - проверяет данные;
   - в одной транзакции ищет свободную комнату и сохраняет бронь со статусом PENDING;
   - сам считает цену (ночи × цена за ночь из базы);
   - вызывает (имитацию) платёжной системы: успех, отказ или таймаут;
   - при успехе ставит CONFIRMED и записывает письмо в `email_outbox`; при отказе удаляет бронь, и комната освобождается.
4. Сервер возвращает JSON с номером брони и статусом, сайт показывает результат.

**Защита от типичных проблем (из Task 06)**
- *Двойная бронь:* проверка и запись идут в одной транзакции, плюс триггер `bookings_no_overlap` в базе не принимает пересекающуюся бронь на ту же комнату.
- *Двойное нажатие «Pay» или обрыв связи:* у каждого запроса есть idempotency key, повторный запрос не создаёт вторую бронь.
- *Безопасность:* сервер не доверяет цене из браузера, в запросе только токен, все SQL-запросы с параметрами (защита от SQL-инъекций), весь пользовательский текст на страницах экранируется (защита от XSS).

## 6. Как работать с Git вместе, чтобы не мешать друг другу

Правила простые:
1. **Не работай напрямую в общей ветке.** У каждого своя ветка и свои файлы (по таблице ролей выше).
2. Перед началом: `git pull`.
3. Создай ветку под свою задачу:
   ```
   git checkout -b имя-задачи
   ```
4. Сделал часть работы, сохрани и отправь:
   ```
   git add .
   git commit -m "Коротко что сделал"
   git push -u origin имя-задачи
   ```
5. На GitHub открой Pull Request и попроси кого-то из команды посмотреть. Только потом слияние с основной веткой.
6. Если правишь файл другого человека (например, общий `styles.css`), сначала напиши ему в чат.
7. **База `backend/hotel.db`** меняется при каждой брони. Перед коммитом верни чистую: `git checkout backend/hotel.db`, либо в панели персонала нажми «Reset all data».

Если Git пишет конфликт, не паникуй: открой файл, найди строки `<<<<<<<`, выбери нужный вариант, удали служебные строки и сделай коммит. Если не получается, спроси в чате.

## 7. Частые проблемы

| Проблема | Что делать |
|---|---|
| `node` не найден | Установи Node.js LTS и перезапусти терминал |
| «needs Node.js 22.5 or newer» | Обнови Node.js до LTS |
| Порт 3000 занят | Закрой другой сервер или запусти на другом порту: Mac/Linux `PORT=3001 node backend/server.js`; Windows `set PORT=3001` и затем `node backend\server.js` |
| Плашка «Demo mode» | Сервер не запущен, или страница открыта не с `http://localhost:3000` |
| Хочу чистую базу | «Reset all data» в панели персонала, либо `git checkout backend/hotel.db` |
| Тестовые карты | `4242 4242 4242 4242` успех; `4000 0000 0000 0002` отказ; `4000 0000 0000 9995` таймаут (статус PENDING). Срок любой будущий, CVC любой |

## 8. Основные API-адреса (для backend и frontend)

| Метод и адрес | Что делает |
|---|---|
| `GET /api/health` | Состояние сервера и базы |
| `GET /api/room-types` | Типы комнат и цены |
| `GET /api/availability?in=ГГГГ-ММ-ДД&out=ГГГГ-ММ-ДД` | Свободные комнаты на даты |
| `POST /api/bookings` | Создать бронь (JSON: гость, тип комнаты, даты, токен карты, idempotency key) |
| `GET /api/bookings?email=...` | Брони гостя |
| `POST /api/bookings/:id/cancel` | Отменить бронь |
| `POST /api/bookings/:id/confirm` | Подтвердить оплату на стойке (сотрудник) |
| `GET /api/staff/bookings`, `GET /api/staff/rooms?date=...` | Данные для панели персонала |
| `GET /api/tables/:name` | Строки таблицы из базы (для страницы Backend) |

Формат запросов и ответов видно на странице бронирования: после брони откройте блок «Show the JSON request and response».
